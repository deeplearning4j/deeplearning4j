### Root Cause: `configureMaxAllocationForKvCache` changes output slot buffer addresses after CUDA graph capture, and `markExternalInputVariable` fails to invalidate the graph

**The bug chain:**

1. **Java warmup** (`GenerationPipeline.java:1557`): `decoder.output(decodeInputMap)` runs the plan, which captures a CUDA graph. The graph bakes in the `specialBuffer()` addresses of all output slots (including KV caches and logits).

2. **Max-allocation** (`GenerationPipeline.java:1646`): `executor.configureMaxAllocationForKvCache()` is called AFTER the warmup graph is captured. This calls `DataBuffer::expand()` on KV output slots, which allocates NEW device buffers at DIFFERENT addresses and frees the old ones. The CUDA graph now has dangling pointers to the old (freed) KV output buffers.

3. **Frozen** (`GenerationPipeline.java:1655`): `executor.setShapesFrozen(true)` is called.

4. **markExternalInputVariable** (`autoregressive_decode.cu:448-455`): Called for variable inputs. On first generation, `needsFullInvalidation = false` because no staging buffers/effectiveExternals have been allocated yet (`NativeDynamicShapePlan.cpp:2660-2663`). Therefore `invalidateSegmentCaptures` is **NOT called**. The stale CUDA graph (with dangling KV output pointers) is kept.

5. **Native decode loop executes** (`autoregressive_decode.cu:525`): `executeSteadyState` → `platformTryFrozenFastPath` finds the replay handle is ready and replays the stale CUDA graph. The graph writes to the old (freed/reallocated) buffer addresses. The logits output slot now has a new buffer that never gets written to → reads as zeros → argmax returns 0 → all tokens are 0.

**Key code locations:**
- `GenerationPipeline.java:1646-1647` — max-allocation after capture (creates address mismatch)
- `NativeDynamicShapePlan.cpp:2660-2663` — `needsFullInvalidation` check returns false on first gen (fails to invalidate)
- `NativeDynamicShapePlan.cpp:2691` — `invalidateSegmentCaptures` never reached
- `DataBuffer.cu:151-170` — `expand()` allocates new device buffer at different address
- `NativeDynamicShapePlan_cuda.cu:376` — CUDA graph replays with stale pointers

**The fix would be one of:**
1. Move `configureMaxAllocationForKvCache` to BEFORE the warmup `decoder.output()` call (so the capture uses the final expanded addresses)
2. Call `invalidateSegmentCaptures` unconditionally in `markExternalInputVariable` (not gated on `needsFullInvalidation`)
3. Track whether `expand()` was called on any output slot and invalidate captures if so
4. Check `capturedSlotAddrHash` after max-allocation to detect the mismatch and invalidate
