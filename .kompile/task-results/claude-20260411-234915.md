### Root Cause Analysis

**Issue 1: `input_ids` not provided to the decoder — HIGH probability**

If `ModelIOConfig.inputIds=null`:
- `ioConfig.isInputIds(name)` always returns false (line 155: `inputIdsName != null && ...`)
- `input_ids` falls through ALL if/else branches in `buildDecoderInputMap` — never added to the feed dict
- `associateInternalModelInputs` skips it (arr is null)
- During `decoder.output()`, if `input_ids` is not a PLACEHOLDER, InferenceSession uses whatever value is already associated (from import or previous run). It does NOT crash — it silently uses stale data.
- If `input_ids` is a PLACEHOLDER but missing → `IllegalArgumentException` at `InferenceSession.java:5726`

**Critical**: For text-only (17-token) validation, `promptTokenIds.length == currentSeqLen` (both 17), so `input_ids` IS provided. For VLM, if ModelIOConfig.inputIds is null, input_ids is never even checked — it's not that the seq_len mismatch at line 766 fires, it's that the `isInputIds()` gate at line 757 never matches.

**Issue 2: `attn_mask_reformat` NOT overridden during prefill — HIGH probability**

At `DecoderUtils.java:829-864`: the 4D attention bias override is only applied when `usePadded=true`. At step 0, `usePadded=false`. So the model computes `attn_mask_reformat` internally via its ONNX subgraph.

If the internal attn_mask_reformat subgraph depends on `input_ids` shape (e.g., `ShapeOf(input_ids)` → seq_len derivation), and `input_ids` has a stale/wrong value, the computed 4D attention bias is incorrect → the model attends to wrong positions → garbage output.

In HuggingFace ONNX exports, the `attn_mask_reformat` subgraph typically computes:
```
seq_len = shape_of(attention_mask)[1]  # or shape_of(input_ids)[1]
causal_mask = triu(full(seq_len, seq_len, -inf), diagonal=1)
combined_mask = attention_mask_expanded + causal_mask
```

If the subgraph uses `input_ids` shape and gets the wrong value, the causal mask dimensions are wrong.
