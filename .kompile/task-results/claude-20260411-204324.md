## Root Cause: `tl_graphExecutionActive` suppresses GPU memory frees during GPU backend execution

### The Leak Path

**File:** `NativeDynamicShapePlan_segments.cpp`, lines 685-699

```cpp
bool needsCaptureSuppression = (seg.exec.currentPhase == ExecutionPhase::COMPILING
    || seg.exec.currentPhase == ExecutionPhase::REPLAYING);
if (needsCaptureSuppression) {
    tl_graphExecutionActive = true;  // LINE 691
}
auto status = backend->executeSegment(...);
if (needsCaptureSuppression) {
    tl_graphExecutionActive = false;  // LINE 699
}
```

When the GPU backend (Triton or CUDA graphs) is in `COMPILING` or `REPLAYING` phase, `tl_graphExecutionActive=true` is set for the duration of `backend->executeSegment()`.

### How This Prevents Frees

**File:** `DataBuffer.cu`, lines 1035-1041

```cpp
if ((tl_graphExecutionActive || tl_captureSkipFrees) && _workspace == nullptr) {
    // SKIP FREE — memory stays allocated
}
```

When `tl_graphExecutionActive=true`, `DataBuffer::deleteSpecial()` **skips `cudaFreeAsync`**. Any `NDArray` deleted during this window leaks its GPU memory. The comment at line 1035 even documents this explicitly:

> *"Recording cudaFreeAsync for graph-external memory creates MemFree graph nodes that reference stale addresses on cudaGraphLaunch → SIGSEGV. The memory stays allocated."*

### Why It Leaks 256 MB/Step

There are three categories of arrays that get "freed" (NDArray deleted) during backend execution but their GPU memory is preserved:

1. **`writeOutputSlot` frees** (`NativeDynamicShapePlan.cpp:328`): When slot outputs are replaced, old arrays are deleted. But `delete old` triggers `DataBuffer::deleteSpecial()` which skips the GPU free. The NDArray wrapper is deleted but the **GPU buffer stays allocated**.

2. **`discardCachedSlotArray` frees** (`NativeDynamicShapePlan_slotexec.cpp:916-917`): Even when `tl_graphExecutionActive=false` at the `discardCachedSlotArray` check (line 915), the downstream `DataBuffer::deleteSpecial` would still be blocked if `tl_graphExecutionActive` was restored to true by the outer scope.

3. **Op-internal temporaries**: Operations like matmul, softmax, and attention allocate temporary workspace arrays internally. These are normally freed after the op completes. With `tl_graphExecutionActive=true`, the GPU memory leaks.

For a 2743-op transformer model:
- ~30 attention layers × ~8 matmul/softmax/attention ops each = ~240 ops with internal temporaries
- Each matmul workspace ≈ 1MB, each attention temp ≈ several MB
- Total: ~256 MB/step
