## Investigation Results: DSP vs Standard InferenceSession Execution Order

### 1. How DSP Determines Slot Order

**`DynamicShapePlanCompiler.java`** (line ~131):
```java
List<ExecutionNode> executionOrder = dag.getExecutionOrder();
```

The compiler iterates through `dag.getExecutionOrder()` sequentially. Each node in this list becomes a slot at index `stepIdx` (0, 1, 2, ...). The slot index directly corresponds to the position in the `executionOrder` list. The compiler builds:
- `slots[stepIdx]` = the op at `executionOrder.get(stepIdx)`
- Input wiring resolves to either negative external indices or positive output slot indices
- The compiled plan is then executed slot 0, 1, 2, ... by `executeSegmentSlotBySlot` in C++ (`NativeDynamicShapePlan_segments.cpp`, line ~819: `while (stepIdx <= seg.def.endSlot)`)

### 3. Are the Orders the Same?

**Yes — both paths use the identical `ForwardExecutionDAG.getExecutionOrder()` list.** This list is built by `ForwardExecutionDAGBuilder.createTopologicalOrder()` which uses a **depth-first recursive topological sort** (post-order DFS):

```java
private void topologicalSort(ExecutionNode node, ...) {
    visiting.add(nodeName);
    for (String depName : node.getDependsOnOperations()) {
        topologicalSort(depNode, ...);  // DFS into dependencies
    }
    visited.add(nodeName);
    result.add(node);  // post-order: add AFTER visiting all deps
}
```

**Key detail:** The iteration order starts with nodes that have no dependencies (`getDependsOnOperations().isEmpty()`), then processes remaining unvisited nodes. Within each DFS traversal, ties are broken by **HashMap iteration order** (non-deterministic unless using `LinkedHashMap`).

### 4. Multiple Valid Topological Orderings — THE CRITICAL FINDING

**Parallel branches ARE a real concern.** The DAG builder uses `HashSet` for dependencies (`Set<String> dependencies = new HashSet<>()`), and `HashMap` for operation nodes. The DFS visits dependencies in **HashMap iteration order**, which is non-deterministic.

In the decoder's attention subgraph (Q/K/V projections), these are parallel branches with no inter-dependencies:
- `q_proj` depends on `input` only
- `k_proj` depends on `input` only  
- `v_proj` depends on `input` only

All three can appear in any relative order (Q→K→V, V→Q→K, K→V→Q, etc.) and still be valid topological sorts. **Both DSP and standard paths would get the same order from the same DAG**, but:

**The critical issue is NOT between DSP vs standard — it's whether the DAG builder produces the same order across different DAG builds.** If the DAG is rebuilt (cache miss, different output set), HashMap ordering could differ.
