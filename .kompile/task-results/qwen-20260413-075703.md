### Critical Changes by Component

#### 1. `DynamicShapePlanExecutor`

**`22432f0e49` — Major refactor (hang fixes, constant caching, mode preservation):**
- **Dead code removal**: Deleted `CapturingSlotInterceptor`, `ExecutionPlan`, `ExecutionPlanCache`, `ExecutionPlanCompiler`, `OpSlot`, `PlanCompileCache`, `PlanExecutor`, `SlotOutputInterceptor` — **2226 lines deleted**. The old Java slot-by-slot execution path was removed.
- **Constant value caching**: Added `cachedConstantValues` map — caches detached copies of small constants (≤32 elements) at compile time to survive session cleanup that force-closes DataBuffers.
- **Dead constant recovery**: On execution, if a constant's DataBuffer is closed, restores from cache instead of creating zeros (which corrupts model weights).
- **syncToDevice for placeholders**: Frozen placeholder inputs are now synced to device before CUDA graph replay (Java-side `putScalar`/`assign` marks host dirty but C++ NDArray wrapper doesn't inherit Java actuality tracking).
- **Mode preservation on recompile**: Plan recompilation now reuses `configuredGraphExecutionMode` instead of resetting to AUTO.
- **`NATIVE_STATUS_STALE_BUFFER` (error code 5)**: New specific error from C++ for closed DataBuffers, throws `IllegalStateException` for caller retry.
- **`syncSavedKvPosition(long)`**: New method to sync Java-side `savedKvCurrentPos` without double-incrementing C++ position.

**`7ff51ae45c` — Permute view strides correctness fix (THE ROOT CAUSE FIX):**
- **Output stride matching**: `executeNative()` now reads strides from C++ output `shapeInfo` and creates Java arrays with `Nd4j.createUninitialized(dtype, shape, strides, ordering)` instead of just shape + ordering.
- **Non-contiguous dup safety**: If C++ output has non-contiguous strides (from permute views), dups to contiguous layout so downstream Java code doesn't misinterpret buffer layout.
- **DSP_DIAG auto-enable**: Auto-enabled by `isDebugAndVerbose()` — no manual env vars needed.
- **Per-slot input/output logging** with `syncToHost` in DSP execution.
- **`compareExecutionPaths()`**: New SameDiff method to run both standard and DSP execution and compare outputs.
- **Dead constant passthrough**: Changed from "create zeros" to "pass original array as-is" for closed DataBuffer constants — creating zeros corrupts model weights.

### Summary: What Changed That Could Affect Execution Correctness

**Most impactful changes (in order):**

1. **`7ff51ae45c` — Permute view strides root cause**: This was THE correctness bug. ONNX stores transpose permutation as input[1] (constant tensor), not iArgs. The DSP executor didn't read it, giving C-contiguous strides instead of permuted strides. This corrupted every permute-after-reshape chain through 30 transformer layers.

2. **`22432f0e49` — 2226-line refactor**: Removed the old Java slot-by-slot execution path entirely. Old `ExecutionPlan`, `PlanExecutor`, etc. deleted. The new native execution path has constant caching, mode preservation, and cross-device routing suppression.

3. **`47a24d3ce4` — 250 MB/step GPU memory leak**: tl_castCache in MmulHelper was growing unboundedly. Fixed by removing push_back calls and adding AutoFreeOnLaunch.

4. **`7ff51ae45c` — `clearNodeOutputsOnly()` vs `clearAllCaches()`**: The decode recompile path now clears only stale outputs, not model constants. `clearAllCaches()` progressively destroyed model weights across recompile cycles.

5. **`7ff51ae45c` — Causal mask per-step update**: In padded decode mode, the causal mask now updates content each step (attend to 0..cachePos, mask the rest). Previously reused stale step-1 mask.

6. **`7ff51ae45c` — KV position sync**: `syncSavedKvPosition()` keeps Java-side position in sync with C++ without double-incrementing, ensuring plan recompilation restores correct position.

7. **Uncommitted — TF32 Triton matmul**: Triton per-element matmul now truncates to TF32 precision to match cuBLAS. This affects numerical output but should improve consistency with cuBLAS baseline.
