This skips:

| Step | Normal Path | Override Path |
|------|------------|---------------|
| `calculateOutputShape()` | Called (line 427) | **Skipped entirely** |

The critical consequence: **no output shape is ever computed or validated**. The op receives whatever pre-allocated arrays DSP placed in `fastpath_out()`, and the op has no way to verify they match what `calculateOutputShape` would have returned.

### 2. Ops Found That Depend on Output Shape During Execute

#### **matmul** — HIGH RISK (`blas/matmul.cpp`)

Reads `z->sizeAt(-1)`, `z->sizeAt(-2)`, and `z->strideAt(...)` for:
- **Reshape strategy for rank-mismatch broadcasts** (lines 86-118): Uses output dimensions to compute the reshaped 2D shape for ND@2D or 2D@ND cases
- **Shape validation** (lines 145-153): Asserts `x->sizeAt(xLastButOneDim) == z->sizeAt(-2)` and `y->sizeAt(yLastDim) == z->sizeAt(-1)`

In the CUDA path (`MmulHelper.cu`), the impact is even more severe:
- **Contiguity checks** via `C->strideAt(0)` / `C->strideAt(1)` (lines 864-871) determine whether a temporary buffer is allocated
- **Leading dimension `ldc`** is derived from `pC->strideAt(1)` (line 888) — if DSP pre-allocates an output with different strides than what `calculateOutputShape` would produce, cuBLAS computes with wrong memory layout
- **`tryBlasStridedBatched`** gate (lines 1534-1536) returns `false` if output isn't row-major contiguous — skipping the optimized cuBLAS path entirely and falling through to slower custom kernels

#### **rms_norm** — MODERATE RISK (`nn/llm_ops.cpp`, lines 62-70)

Checks output contiguity:
```cpp
const bool outputContiguous = output->ordering() == 'c' &&
                              shape::strideDescendingCAscendingF(output->shapeInfo());
```

If the DSP-pre-allocated output has different strides than expected:
- The fused CPU/CUDA helper paths are skipped
- A temporary contiguous buffer is created, computed into, then `assign()`ed back
- The `assign()` into a non-contiguous target could produce different memory ordering than writing directly to a contiguous output

#### **onnx_multi_head_attention** — LOW RISK

The op is purely input-driven. All computation parameters (batch, seq lengths, head dims) are derived from **input** tensors. The output is only used as a write target for `assign()`. No output shape queries found.

### 3. Root Cause

The bug is that `shapeFunctionOverride` is a **global flag** applied to all ops uniformly. It assumes that DSP's pre-allocated outputs are always shape-identical to what `calculateOutputShape` would produce. This is true for simple ops (identity shape functions like `rms_norm`), but **not guaranteed** for:

1. **Ops that reshape during execution** — `matmul` reshapes outputs for rank-mismatch broadcasts. If DSP's shape function returns shape A but the execute path reshapes to shape B internally, the cuBLAS call operates on the wrong layout.

2. **Ops where strides matter** — cuBLAS dispatch (`tryBlasStridedBatched`) requires specific stride patterns. If DSP pre-allocates an output with strides that don't match what the cuBLAS path expects, either the wrong kernel is selected or the kernel computes with wrong memory layout.

3. **Ops with conditional execution paths** — `norm` uses `output->rankOf()` to pick reduction overloads. If the pre-allocated output has a different rank than expected, the wrong code path executes.

---

### 4. Recommended Fix

The fix should be **op-specific**, not removing the override globally. Two approaches:

**Option A — Per-op opt-out:** Add a virtual method to `DeclarableOp`:
```cpp
virtual bool requiresShapeValidationDuringExecute() const { return false; }
```
Override to `true` for `matmul` and any other affected ops. In `prepareOutputs()`, skip the early return for these ops, ensuring `calculateOutputShape` runs and validation happens.

**Option B — Always validate shapes in execute:** In the warmup path, instead of setting `shapeFunctionOverride(true)`, set a flag that tells `prepareOutputs` to skip **allocation** but still run `calculateOutputShape` and validate. The pre-allocated arrays are kept if shapes match; replaced if they don't.

**Option B is safer** — it preserves the DSP pre-allocation intent while catching shape mismatches. **Option A is more targeted** but requires auditing every op for correctness.
